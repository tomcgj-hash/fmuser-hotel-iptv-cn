03 — SIGNAL FLOW

系统图与三层架构

黑屏的原因，八成不在设备坏，而在组播没开或 VLAN 没划。

四段式：信号进来、前端处理、网络分发、客房播放。看图只盯两件事——节目从哪来、每台电视走组播还是单播。

组播 UDP单播 HTTP/HLSIGMP Snooping
虚线 = 信号流（UDP 组播 / HLS） 实线框 = 我们交付 斜线填充 = 软件与授权
A

四段逐段看

每段四件事，够你判断这一层要不要自己买。

STEP 01

① 信号源

  • 卫星天线 1.8–3.7 m
  • C 波段 LNB / BPF-C
  • 有线电视 / 运营商 IPTV
  • HDMI 编码器（自办频道）
STEP 02

② 前端机房

  • FBE308U / FBE302 接收解扰
  • FBE700 / FBE900 服务器
  • 协议转换 + 组播分发
  • IPTV 业务系统
STEP 03

③ 网络

  • 核心交换机（机房）
  • 接入交换机（弱电井）
  • VLAN 隔离 + IGMP
  • 跨楼栋光纤
STEP 04

④ 客房

  • FBE013 机顶盒
  • 或安卓电视装 APK
  • 酒店模式 + 欢迎页
  • PMS 账单一键查

NOTE 很多人以为 IPTV 就是把电视接到网线上。实际是两件事同时成立——节目流按组播分发、客房终端有账号与频道表。前者靠交换机配置，后者靠前端业务系统。

B

协议怎么用：组播省带宽，单播管点播

← 左右滑动查看完整表格 →
组播（UDP Multicast） 一场直播只发一份到交换机，交换机按需复制到端口。带宽省、延迟低，是酒店直播的主力方式。需要交换机开启 IGMP Snooping。
单播 HTTP / HLS 每个终端一条流。点播、回看、移动端播放用它；并发一多就吃带宽，所以点播走本地服务器存储。
SRT / RTMP 用于跨站点回传、推到外部平台。SRT 抗丢包，适合公网链路不稳的场合。
协议转换 前端把 HTTP / HLS / RTSP 转成 UDP 组播，或把 TS 文件循环播成频道，终端只认一种源，运营排错简单。
C

机房要交代给施工方的三句话

01

客房网段要开 IGMP Snooping

不开的话组播会泛洪到所有端口，看着能播，实际把整栋楼带宽吃光。

02

IPTV VLAN 与办公网、客用 WiFi 分开

同一张网里跑电视和客人上网，任何一侧出故障都会互相牵连。

03

服务器与核心交换机放同一机柜，UPS 至少撑 30 分钟

断电后能让直播平稳收尾，也避免硬盘写坏。

D

实例：一栋两层怎么组：一层有线、一层无线

同一个前端，两种客房接入方式并存。这张是一栋度假公寓的实际组网（FBE803 方案）。

A 信号进机房

屋顶卫星（C/Ku 波段）与地面 DVB-T2 同时进机房，分别用接收机解调；自办频道走 HDMI 编码器。

B 前端与冗余

网关设备做主备（一台工作一台待命），交换机到 OLT 走光口；这一段的配置决定全楼能不能看。

C 楼层两种接法

一层走 CAT6 有线（稳定、免维护）；二层走 WiFi6（省布线、适合不便开墙的楼层）。两层共用同一套频道表。

提示：无线那层只建议承载点播与欢迎页，直播仍优先走有线；如果二层也必须看直播，建议把 AP 与电视放在同一房间并单独划 VLAN。
